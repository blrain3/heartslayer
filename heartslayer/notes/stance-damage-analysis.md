# 姿态数据分析：姿态判断到底有没有实际影响决策？

结论先行：**没有证据表明姿态判断在伤害层面造成可观测损失。** 这次数据不支持"WRATH 挨打更多"的假设，方向甚至相反。

## 数据来源（bot 自己能看到的，所以这是 bot 决策时可得的信息）

日志里 response 的 `game_state` **没有 stance 字段**（已验证 0/266 条 Response 含 "stance"）。
唯一可用的姿态来源是 bot 自己的 memory 快照：

```
Memory of next action: {..., <MemoryItem.STANCE: 14>: <StanceType.WRATH: 3>, ...}
```

用 `current_hp` 差值恢复承伤，只保留同房间、floor 非递减的相邻观测配对。

## 结果（29 局，按 act 分层）

受击步占比 = 该姿态下 HP 实际下降的观测 / 该姿态全部观测

| act | WRATH | NO_STANCE | CALM | DIVINITY |
|-----|-------|-----------|------|----------|
| 1   | 2.4% (52/2185) | 7.8% (100/1286) | 7.2% (41/568) | 0% (0/13) |
| 2   | 1.8% (32/1771) | 5.0% (39/784)  | 6.5% (40/620) | 1.1% (1/92)  |
| 3   | 1.7% (27/1577) | 5.1% (42/827)  | 5.9% (33/557) | 2.1% (4/195) |

## 怎么读这组数字

WRATH 的受击比例是 CALM 的约 1/3。这**不代表 WRATH 更安全**，而是说明
bot 进入 WRATH 的时刻大多不在敌人攻击窗口内（刚清场、或敌人非攻击回合）。
姿态与承伤的因果关系无法从观测日志直接建立 —— 缺"同一步如果不进 WRATH 会怎样"的
反事实。

另需说明：早期（未分层）版本给出 WRATH mean=11.8 / median=3 的巨大背离，
那是少数重击的右偏分布，不能读成"WRATH 平均多挨 12 点"。分层后中位数与均值都回落。

## 对"stance_is_not_wrath 排名靠后"这个问题的回答

排第 38/42 位本身**不构成 bug 证据**。理由：

1. 前 37 项多为硬数值比较（least_incoming_damage_over_1 等），几乎总能分出胜负，
   后置项本来就不容易成为决胜因子。
2. 数据层面看不到 WRATH 造成额外承伤的稳定信号，所以即使前置也不会有可证明的收益。
3. 没有反事实，任何"如果早点判断姿态就能少挨打"的说法都无法验证。

**结论：姿态判断暂不动代码。** 若要继续推进，正确的下一步不是改比较器顺序，
而是做可控实验（同一 seed 强制 WRATH 结束 vs 强制 CALM 结束，比较结果），
那需要种子与日志联动，属下一阶段的事。
